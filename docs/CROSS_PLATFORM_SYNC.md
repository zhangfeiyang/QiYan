# App / 微信小程序同步规范

## 原则

- 产品能力、难度等级、段位说明等跨端配置，以 `shared/config/` 为唯一事实来源。
- Android 与小程序可使用不同 UI 和平台 API，但用户可见规则、文案含义、功能状态必须一致。
- 修改跨端功能时，同一提交必须更新 `shared/config/features.json`、Android 实现和小程序实现；平台受限功能必须填写明确的 `roadmap`。
- 提交前运行 `node tools/sync-shared-config.mjs` 和 `node tools/check-platform-sync.mjs`。

## 平台边界

Android 的 Pikafish 通过 NDK/JNI 本地运行，微信小程序无法直接加载该原生库。小程序对弈和局面分析通过后端引擎服务提供，走法合法性、棋盘交互和对局状态在小程序本地完成。后端接口必须使用与 Android 相同的 1-15 级映射。

拍照识局、实时支招需要把 ONNX 推理迁移到服务器或微信云托管；在完成前，能力矩阵会明确显示为待同步，不用不可运行的假入口冒充已完成。

## 更新流程

1. 先改共享规范和能力矩阵。
2. 同一分支分别完成 Android 与小程序实现。
3. 生成小程序配置并运行双端测试。
4. 仅当能力矩阵和自动检查通过时提交。
