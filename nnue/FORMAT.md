# 自研 NNUE 数据与特征格式

> 数据全部来自**本项目引擎的自对弈**, 不接触 Pikafish 或任何 GPL 引擎的输出。
> 这是刻意的约束: 蒸馏别人的网络会让权重成为衍生作品, 参见 Fat Fritz 2 案例。

## 一、特征编码 (Kotlin 与 Python 必须逐位一致)

象棋 90 个交叉点, 14 种棋子(红黑各 7 种)。

棋子索引 `pieceIdx`(0..13), 顺序**固定**, 改动即作废已有数据:

| idx | 子 | idx | 子 |
|----:|----|----:|----|
| 0 | 帅 K | 7 | 将 k |
| 1 | 仕 A | 8 | 士 a |
| 2 | 相 B | 9 | 象 b |
| 3 | 马 N | 10 | 马 n |
| 4 | 车 R | 11 | 车 r |
| 5 | 炮 C | 12 | 炮 c |
| 6 | 兵 P | 13 | 卒 p |

格子索引 `sq = row * 9 + col`, `row 0` = 黑方底线(与 Position 内部约定一致)。

**单视角特征下标**: `featIdx = pieceIdx * 90 + sq`, 取值范围 0..1259。

### 双视角

NNUE 用两个累加器: 走子方视角 + 对方视角。对方视角要把棋盘上下翻转
**并且红黑互换**, 这样网络学到的是"我方/敌方"而不是"红方/黑方", 参数利用率翻倍。

- 我方视角: `own(piece, sq) = idx(piece) * 90 + sq`
- 敌方视角: `opp(piece, sq) = idx(flipColor(piece)) * 90 + flipSquare(sq)`
  - `flipSquare(sq) = (9 - row) * 9 + col`   (只翻行, 列不动)
  - `flipColor`: 红↔黑 同名子互换, 即 `idx` 在 0..6 与 7..13 之间加减 7

## 二、网络结构

```
输入  own[1260]  opp[1260]        稀疏, 每边最多 32 个 1
        │          │
   FeatureTransformer (共享权重 1260→256)
        │          │
      acc_own    acc_opp     各 256 维
        └────┬─────┘
          concat 512
             │ ClippedReLU
            32
             │ ClippedReLU
            32
             │
             1  →  厘兵分 (centipawn)
```

共享 FeatureTransformer 是关键: 同一套权重同时服务两个视角, 参数量减半且
天然获得"红黑对称"的先验。

## 三、样本文件格式 (`.bin`, 小端)

每条样本定长 **36 字节**:

| 偏移 | 类型 | 含义 |
|---:|---|---|
| 0  | u8[32] | 棋子列表, 每字节 `(pieceIdx << 7) \| sq` 打不下, 见下 |
| -  | - | 实际用 2 字节/子 |

**修订**: 每条样本 **72 字节**

| 偏移 | 类型 | 含义 |
|---:|---|---|
| 0 | u8 | `count` 棋盘上棋子数 (最多 32) |
| 1 | u8 | `sideToMove` 0=红 1=黑 |
| 2 | i16 | `score` 走子方视角的厘兵分, 已截断到 ±10000 |
| 4 | u8[64] | `count` 个 `(pieceIdx, sq)` 对, 每对 2 字节; 余下补 0 |
| 68 | i16 | `depth` 打这个标签时的搜索深度 |
| 70 | u8[2] | 保留, 置 0 |

定长是为了让训练侧能 `np.fromfile` 直接 reshape, 不必逐条解析。

## 四、标签约定

- **分数始终是走子方视角**(正 = 走子方占优), 与引擎内部 negamax 约定一致。
- 截断到 ±10000: 杀棋分数(±30000 量级)会把回归目标的尺度带偏, 统一压到边界。
- 训练目标用 `tanh(score / 400)` 压到 (-1,1), 这是 Stockfish 系惯用的
  分数→胜率映射尺度, 让损失不被少数极端分数主导。
